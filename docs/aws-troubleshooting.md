# AWS deployment troubleshooting

Inspect the specific failing layer. Do not broaden IAM/security groups, make S3 public, disable certificate validation or use plaintext credentials as a workaround. Keep identifiers private and never share .env/pgpass/private keys, environment dumps or AWS tokens with logs.

| Symptom | Safe checks and resolution |
| --- | --- |
| AWS CLI missing / expired token | Install CLI v2; use aws login --profile campusshift after the scoped IAM/MFA setup. Run STS identity in the selected region. No live permissions have been verified in the development environment. |
| AccessDenied / unauthorized operation | Record the operation and error code, not credentials. Separate Free Plan restrictions from missing scoped IAM permissions. Review only the required actions; do not grant AdministratorAccess, reuse LabRole, join Organizations, upgrade or switch accounts to bypass a denial. A successful CloudFormation validation does not prove EC2/RDS/S3 creation rights. |
| CloudFormation CREATE_FAILED | Inspect `describe-stack-events` for the exact logical resource; check VPC/subnet AZs, SG quotas, managed prefix list, available instance/RDS class, KMS/SSM decrypt and IAM pass-role. Leave existing resources/data intact. Review rollback and retained-resource costs before creating another stack. |
| SecureString resolution fails | Confirm approved parameter path and exact version exist in the same account/region, type is SecureString, KMS key is permitted and CloudFormation can resolve it. Never print the value. If blocked, report RDS secret delivery blocked; use the reviewed PostgreSQL-on-EC2 fallback if authorized. |
| EC2 bootstrap incomplete | `cloud-init status`, `/var/log/cloud-init-output.log`, disk space, Internet Gateway route and outbound package access. Verify Python 3.11 and Nginx packages on the actual AL2023 AMI. No secret should be in user-data. |
| SSH timeout / changed host key | Verify stack's current public IP, administrator `/32`, key pair and public-subnet route. Verify a new host fingerprint via an approved channel; do not disable StrictHostKeyChecking or blindly accept a changed fingerprint. |
| API works locally, CloudFront 502 | From EC2 use `curl --resolve DOMAIN:443:127.0.0.1 https://DOMAIN/api/ready`; check certificate chain/expiry/name, DNS->current EC2 IP, Nginx TLS, CF origin domain and HTTPS-only configuration. Default CloudFront viewer TLS cannot replace origin TLS. No `-k` or public HTTP fallback. |
| CloudFront 403 for frontend | Confirm distribution Deployed, S3 bucket policy SourceArn matches distribution, OAC signing enabled, objects uploaded and private S3 REST origin used. Keep public access blocked. Missing object responses can be S3 403. |
| SPA deep link fails | Confirm viewer-request Routes function association/publish and extensionless URI rewrite. API routes must never rewrite to index. Verify assets exist and index belongs to the same release. |
| Login 401 or repeated sign-out | Verify actual seeded fictional account/password and configured JWT lifetime. Public registration creates students only. Tokens remain in memory and browser refresh signs out by design. Do not send tokens in URLs or logs. Check server time. |
| Login 503 | Check protected JWT configuration and database readiness; never print the signing secret. Production refuses SQLite/weak secrets. Apply migrations with the service user's environment and verify readiness. |
| Role 403 / ownership 404 | These may be expected security behavior. Use a supervisor provisioned explicitly in the correct department; do not promote a public-registration account via an unrestricted endpoint. |
| PostgreSQL connection/SSL failure | Confirm RDS available, private endpoint, DB SG from backend only, host/name/user and `sslmode=verify-full`/official CA. Ensure passfile is owned by campusshift with mode 0600 and matching host/port/database/user; passwords containing colon/backslash must be escaped. Never expose port 5432 publicly. |
| Migration permission failure | Use the dedicated application's database owner role for migration. Confirm target DB/schema ownership and full migration chain; do not grant superuser or use create_all to bypass Alembic. Preserve prior SQLite data; no automatic cross-database copy exists. |
| PG concurrency conflict 409 | Refresh the current schedule/attendance revision and review the other change. Advisory locks serialize API writes; unique constraints reject duplicates. A stale pending correction must be rejected/resubmitted. Do not disable the index or silently retry an outdated edit. |
| Nginx upstream permission denied | Inspect SELinux policy and `httpd_can_network_connect` using approved distribution configuration. Keep SELinux enforcing; Uvicorn should listen on loopback only. |
| Service won't start / restart loop | Inspect `systemctl status`, `journalctl -u campusshift`, `/var/log/campusshift/application.log`, current symlink and file permissions. Check correct Python, installed scheduler/psycopg, read permission for env/passfile and log directory. Fix cause then `systemctl reset-failed` and restart explicitly. |
| Clock-in rejected | Check department timezone, current published shift ownership, availability of real server clock window and active/duplicate attendance. Seeded historical shifts cannot be clocked in now; use correction workflow or publish an eligible current shift. |
| CloudWatch empty | Optional log group creation does not install/start an agent or grant permissions. Check explicitly allowed existing profile, agent logs and log stream/put permissions. If blocked, use protected local logs and report it. |
| Resource missing / Free Plan expired | Follow sandbox-recovery.md (legacy filename). RDS Retain/S3 versioning do not protect against account closure, deliberate deletion or compromised credentials. Restore only approved synthetic backups into empty targets. |

For origin networking, inspect `sudo ss -lntp`, `sudo nginx -t` and EC2 SGs. For DB-backed readiness use `/api/ready`; `/api/health` only confirms the API process responds. CloudFront prefix lists have significant SG-rule weight; check the quota before adding rules. The origin prefix list admits other CloudFront distributions too: rely on backend authorization and document the residual distribution-bypass limitation.

Read-only discovery never proves creation permissions. Record each capability as confirmed read/confirmed real deployment, not yet tested or blocked, with the exact evidence. Certificate/domain provisioning, server reboot recovery, public UI interactions, real RDS restore and full cloud recreation must be verified on the actual approved deployment.
